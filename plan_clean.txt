## 2. New SQLAlchemy Models

File: `backend/app/models_clinical.py`

The existing `models.py` uses `from sqlalchemy.ext.declarative import declarative_base` and defines a module-level `Base`. The new models must share the same `Base` object so `Base.metadata.create_all` picks them all up. The cleanest approach is to move `Base` into a separate `backend/app/base.py` module and import it in both files, then import both model files in `main.py`. Alternatively, import `Base` from `models` in `models_clinical.py`.

```python
# backend/app/models_clinical.py

from datetime import datetime, timezone
from sqlalchemy import Column, Integer, String, Float, Date, Text, DateTime, ForeignKey, Boolean
from sqlalchemy.orm import relationship
from models import Base  # reuse same declarative Base


def _now():
    return datetime.now(timezone.utc)


class ClinicalStudy(Base):
    __tablename__ = "clinical_studies"

    id              = Column(Integer, primary_key=True, index=True)
    study_oid       = Column(String, unique=True, index=True, nullable=False)  # e.g. "CARDIO-2024"
    protocol_name   = Column(String, nullable=False)
    phase           = Column(String)           # "Phase III"
    sponsor         = Column(String)
    therapeutic_area = Column(String)
    objective       = Column(Text)
    status          = Column(String, default="Active")  # Active | Completed | Terminated
    created_at      = Column(DateTime, default=_now)

    subjects = relationship("ClinicalSubject", back_populates="study")


class ClinicalSubject(Base):
    __tablename__ = "clinical_subjects"

    id              = Column(Integer, primary_key=True, index=True)
    study_id        = Column(Integer, ForeignKey("clinical_studies.id"), nullable=False)
    subject_key     = Column(String, index=True, nullable=False)  # "CARDIO-2024-001-001"
    site_id         = Column(String)            # "SITE-001"
    site_name       = Column(String)            # "London Cardiology Centre"
    age             = Column(Integer)
    sex             = Column(String)            # M | F
    race            = Column(String)
    enrollment_date = Column(Date)
    status          = Column(String, default="Enrolled")  # Enrolled | Completed | Withdrawn
    created_at      = Column(DateTime, default=_now)

    study    = relationship("ClinicalStudy", back_populates="subjects")
    visits   = relationship("ClinicalVisit", back_populates="subject")


class ClinicalVisit(Base):
    __tablename__ = "clinical_visits"

    id              = Column(Integer, primary_key=True, index=True)
    subject_id      = Column(Integer, ForeignKey("clinical_subjects.id"), nullable=False)
    visit_oid       = Column(String)            # "SCREENING", "DAY1", etc.
    visit_name      = Column(String)            # human label
    visit_date      = Column(Date)
    status          = Column(String, default="Completed")  # Completed | Missed | Pending
    created_at      = Column(DateTime, default=_now)

    subject = relationship("ClinicalSubject", back_populates="visits")
    forms   = relationship("ClinicalForm", back_populates="visit")


class ClinicalForm(Base):
    __tablename__ = "clinical_forms"

    id              = Column(Integer, primary_key=True, index=True)
    visit_id        = Column(Integer, ForeignKey("clinical_visits.id"), nullable=False)
    form_oid        = Column(String)            # "VS", "AE", "CM", "LB"
    form_name       = Column(String)            # "Vital Signs", "Adverse Events", etc.
    data_json       = Column(Text)              # JSON blob of all item/value pairs
    created_at      = Column(DateTime, default=_now)

    visit = relationship("ClinicalVisit", back_populates="forms")


class DocumentChunk(Base):
    __tablename__ = "document_chunks"

    id            = Column(Integer, primary_key=True, index=True)
    source_type   = Column(String, index=True)  # "study" | "subject" | "visit" | "adverse_event" | "lab"
    source_id     = Column(Integer, index=True)  # FK to relevant table row id (informational, no DB FK)
    chunk_text    = Column(Text, nullable=False)
    # Vector stored as Text in SQLAlchemy; raw SQL used for pgvector operations
    embedding     = Column(Text)                # placeholder; actual column type set via raw DDL in migration
    metadata_json = Column(Text)               # JSON: {"study_oid": ..., "subject_key": ..., ...}
    created_at    = Column(DateTime, default=_now)
```

The `embedding` column needs the pgvector type `vector(768)`. SQLAlchemy does not know this type natively, so the migration creates the column via raw SQL rather than `sa.Column`. The Python model maps it as `Text` for ORM-level access but queries use `func` and raw SQL strings for similarity search.

## 4. Service Layer Design

### `backend/app/services/llm.py`

Thin synchronous HTTP wrapper around the Ollama REST API. Uses the existing `requests` library (already in requirements) to keep the pattern synchronous like all other services.

```python
import os, requests, json

OLLAMA_BASE = os.getenv("OLLAMA_URL", "http://ollama:11434")
EMBED_MODEL  = os.getenv("OLLAMA_EMBED_MODEL", "nomic-embed-text")
LLM_MODEL    = os.getenv("OLLAMA_LLM_MODEL", "tinyllama")


def embed_text(text: str) -> list[float]:
    """
    Call POST /api/embeddings on Ollama.
    Returns list[float] of length 768.
    Raises requests.HTTPError on failure.
    """
    resp = requests.post(
        f"{OLLAMA_BASE}/api/embeddings",
        json={"model": EMBED_MODEL, "prompt": text},
        timeout=30,
    )
    resp.raise_for_status()
    return resp.json()["embedding"]  # list[float]


def generate_text(prompt: str, system: str = "") -> str:
    """
    Call POST /api/generate on Ollama (non-streaming).
    Returns the generated string.
    """
    payload = {
        "model": LLM_MODEL,
        "prompt": prompt,
        "stream": False,
    }
    if system:
        payload["system"] = system
    resp = requests.post(
        f"{OLLAMA_BASE}/api/generate",
        json=payload,
        timeout=120,
    )
    resp.raise_for_status()
    return resp.json()["response"]


def ollama_ready() -> bool:
    """Health-check: returns True if Ollama is reachable."""
    try:
        resp = requests.get(f"{OLLAMA_BASE}/api/tags", timeout=5)
        return resp.ok
    except Exception:
        return False
```

### `backend/app/services/ingestion.py`

Builds text chunks from the clinical database, calls `llm.embed_text`, stores results in `document_chunks`. This is called by the `/rag/ingest` endpoint.

```python
import json
from sqlalchemy.orm import Session
from sqlalchemy import text

from models_clinical import ClinicalStudy, ClinicalSubject, ClinicalVisit, ClinicalForm, DocumentChunk
from services.llm import embed_text


def _vector_literal(embedding: list[float]) -> str:
    """Format a Python list as a pgvector literal '[0.1,0.2,...]'."""
    return "[" + ",".join(str(v) for v in embedding) + "]"


def _upsert_chunk(db: Session, source_type: str, source_id: int,
                  chunk_text: str, metadata: dict) -> None:
    """Embed and insert a single chunk. Deletes existing chunk for same source first."""
    db.query(DocumentChunk).filter(
        DocumentChunk.source_type == source_type,
        DocumentChunk.source_id == source_id,
    ).delete()

    vector = embed_text(chunk_text)
    vector_str = _vector_literal(vector)
    metadata_json = json.dumps(metadata)

    # Use raw SQL for vector insert because SQLAlchemy doesn't know vector type
    db.execute(text(
        """
        INSERT INTO document_chunks (source_type, source_id, chunk_text, embedding, metadata_json, created_at)
        VALUES (:source_type, :source_id, :chunk_text, CAST(:embedding AS vector), :metadata_json, NOW())
        """
    ), {
        "source_type": source_type,
        "source_id": source_id,
        "chunk_text": chunk_text,
        "embedding": vector_str,
        "metadata_json": metadata_json,
    })


def ingest_all(db: Session) -> int:
    """
    Build all text chunks from the clinical database and embed them.
    Returns total chunks created.
    """
    count = 0
    studies = db.query(ClinicalStudy).all()

    for study in studies:
        # Chunk 1: Study summary
        text_study = (
            f"Study: {study.study_oid}. Protocol: {study.protocol_name}. "
            f"Phase: {study.phase}. Sponsor: {study.sponsor}. "
            f"Therapeutic area: {study.therapeutic_area}. "
            f"Objective: {study.objective}. Status: {study.status}."
        )
        _upsert_chunk(db, "study", study.id, text_study,
                      {"study_oid": study.study_oid})
        count += 1

        subjects = db.query(ClinicalSubject).filter(
            ClinicalSubject.study_id == study.id
        ).all()

        for subj in subjects:
            # Chunk 2: Subject summary
            text_subj = (
                f"Subject {subj.subject_key} enrolled in study {study.study_oid}. "
                f"Site: {subj.site_name} ({subj.site_id}). "
                f"Age: {subj.age}, Sex: {subj.sex}, Race: {subj.race}. "
                f"Enrollment date: {subj.enrollment_date}. Status: {subj.status}."
            )
            _upsert_chunk(db, "subject", subj.id, text_subj,
                          {"study_oid": study.study_oid, "subject_key": subj.subject_key})
            count += 1

            visits = db.query(ClinicalVisit).filter(
                ClinicalVisit.subject_id == subj.id
            ).all()

            for visit in visits:
                forms = db.query(ClinicalForm).filter(
                    ClinicalForm.visit_id == visit.id
                ).all()
                form_data = {f.form_oid: json.loads(f.data_json) for f in forms if f.data_json}

                # Chunk 3: Visit summary (vital signs + key metrics)
                vs = form_data.get("VS", {})
                text_visit = (
                    f"Subject {subj.subject_key}, visit {visit.visit_name} "
                    f"on {visit.visit_date}. Status: {visit.status}. "
                )
                if vs:
                    text_visit += (
                        f"Vital signs: HR {vs.get('heart_rate')} bpm, "
                        f"BP {vs.get('systolic_bp')}/{vs.get('diastolic_bp')} mmHg, "
                        f"Temp {vs.get('temperature')} C, Weight {vs.get('weight')} kg."
                    )
                _upsert_chunk(db, "visit", visit.id, text_visit,
                              {"study_oid": study.study_oid,
                               "subject_key": subj.subject_key,
                               "visit_name": visit.visit_name})
                count += 1

                # Chunk 4: Adverse events (one chunk per AE in the visit)
                ae_list = form_data.get("AE", {}).get("events", [])
                for ae in ae_list:
                    text_ae = (
                        f"Adverse event for subject {subj.subject_key} at visit "
                        f"{visit.visit_name}: {ae.get('term')}. "
                        f"Severity: {ae.get('severity')}. "
                        f"Relationship to study drug: {ae.get('relationship')}. "
                        f"Outcome: {ae.get('outcome')}."
                    )
                    _upsert_chunk(db, "adverse_event", visit.id, text_ae,
                                  {"study_oid": study.study_oid,
                                   "subject_key": subj.subject_key,
                                   "visit_name": visit.visit_name,
                                   "ae_term": ae.get("term")})
                    count += 1

                # Chunk 5: Abnormal lab results
                lb_results = form_data.get("LB", {}).get("results", [])
                abnormal = [r for r in lb_results if r.get("flag") in ("H", "L", "HH", "LL")]
                if abnormal:
                    lab_lines = ", ".join(
                        f"{r['test']} {r['value']} {r['unit']} ({r['flag']})"
                        for r in abnormal
                    )
                    text_lab = (
                        f"Abnormal lab results for subject {subj.subject_key} "
                        f"at visit {visit.visit_name}: {lab_lines}."
                    )
                    _upsert_chunk(db, "lab", visit.id, text_lab,
                                  {"study_oid": study.study_oid,
                                   "subject_key": subj.subject_key,
                                   "visit_name": visit.visit_name})
                    count += 1

    db.commit()
    return count
```

### `backend/app/services/rag.py`

Implements the retrieval + generation pipeline.

```python
import json
from sqlalchemy.orm import Session
from sqlalchemy import text

from services.llm import embed_text, generate_text


SYSTEM_PROMPT = """You are a clinical trial data assistant for the CARDIO-2024 Phase III study.
Answer questions accurately based only on the context provided.
If the context does not contain enough information, say so clearly.
Do not invent data. Use clinical terminology appropriately."""


def retrieve_chunks(db: Session, question: str, top_k: int = 5) -> list[dict]:
    """
    Embed the question and run a cosine similarity search via pgvector.
    Returns list of dicts with chunk_text, source_type, source_id, similarity.
    """
    q_vector = embed_text(question)
    vector_str = "[" + ",".join(str(v) for v in q_vector) + "]"

    rows = db.execute(text(
        """
        SELECT id, source_type, source_id, chunk_text, metadata_json,
               1 - (embedding <=> CAST(:q_vec AS vector)) AS similarity
        FROM document_chunks
        ORDER BY embedding <=> CAST(:q_vec AS vector)
        LIMIT :top_k
        """
    ), {"q_vec": vector_str, "top_k": top_k}).fetchall()

    return [
        {
            "chunk_text": row.chunk_text,
            "source_type": row.source_type,
            "source_id": row.source_id,
            "metadata": json.loads(row.metadata_json) if row.metadata_json else {},
            "similarity": float(row.similarity),
        }
        for row in rows
    ]


def build_prompt(question: str, chunks: list[dict]) -> str:
    """Assemble the LLM prompt with retrieved context."""
    context_lines = []
    for i, chunk in enumerate(chunks, start=1):
        context_lines.append(f"[Source {i} - {chunk['source_type']}]\n{chunk['chunk_text']}")

    context_block = "\n\n".join(context_lines)
    return (
        f"Context:\n{context_block}\n\n"
        f"Question: {question}\n\n"
        f"Answer based strictly on the context above:"
    )


def answer_question(db: Session, question: str, top_k: int = 5) -> dict:
    """
    Full RAG pipeline:
      1. Embed question
      2. pgvector cosine search (top_k chunks)
      3. Build prompt
      4. Ollama LLM generate
      5. Return answer + sources
    """
    chunks = retrieve_chunks(db, question, top_k=top_k)
    if not chunks:
        return {
            "answer": "No relevant clinical data found. Please run data ingestion first.",
            "sources": [],
            "model": "tinyllama",
        }

    prompt = build_prompt(question, chunks)
    answer = generate_text(prompt, system=SYSTEM_PROMPT)

    sources = [
        {
            "chunk_text": c["chunk_text"],
            "source_type": c["source_type"],
            "source_id": c["source_id"],
            "similarity": c["similarity"],
        }
        for c in chunks
    ]

    return {"answer": answer, "sources": sources, "model": "tinyllama"}
```

Structure: Study -> Subjects -> Visits -> Forms -> Items
All data is deterministic (seeded RNG) so re-seeding is idempotent.

import json
import random

from sqlalchemy.orm import Session
from models_clinical import ClinicalStudy, ClinicalSubject, ClinicalVisit, ClinicalForm

def _weighted(rng: random.Random, options: list[tuple]) -> str:
    population = [item for item, weight in options for _ in range(weight)]
    return rng.choice(population)


def _generate_vitals(rng: random.Random, visit_num: int) -> dict:
    """Vital signs with slight progression over trial."""
    base_hr  = rng.randint(60, 100)
    base_sys = rng.randint(110, 150)
    base_dia = rng.randint(70, 95)
    return {
        "heart_rate":    base_hr + rng.randint(-5, 5),
        "systolic_bp":   base_sys - visit_num * rng.randint(0, 3),
        "diastolic_bp":  base_dia - visit_num * rng.randint(0, 2),
        "temperature":   round(36.2 + rng.uniform(0, 1.2), 1),
        "weight":        round(rng.uniform(58, 105), 1),
        "height":        rng.randint(155, 190),
    }


def _generate_labs(rng: random.Random) -> dict:
    """Lab panel with occasional abnormal values (20% chance per analyte)."""
    results = []
    for code, name, unit, lo, hi in LAB_TESTS:
        # 80% in range, 20% out of range
        if rng.random() < 0.8:
            value = round(rng.uniform(lo, hi), 2)
            flag = "N"
        elif rng.random() < 0.5:
            value = round(rng.uniform(hi, hi * 1.4), 2)
            flag = "HH" if value > hi * 1.3 else "H"
        else:
            value = round(rng.uniform(lo * 0.6, lo), 2)
            flag = "LL" if value < lo * 0.7 else "L"
        results.append({"test": code, "name": name, "value": value, "unit": unit, "flag": flag})
    return {"results": results}


def _generate_aes(rng: random.Random, visit_num: int) -> dict:
    """0-2 adverse events per visit, more likely in later visits."""
    n_ae = rng.choices([0, 1, 2], weights=[70, 20, 10])[0]
    if visit_num == 0:  # Screening: no AEs
        n_ae = 0
    events = []
    for _ in range(n_ae):
        term, sev, rel, outcome = rng.choice(AE_TERMS)
        events.append({
            "term": term, "severity": sev,
            "relationship": rel, "outcome": outcome,
        })
    return {"events": events}


def _generate_meds(rng: random.Random) -> dict:
    """Concomitant medications."""
    meds = rng.sample([
        "Aspirin 75mg", "Bisoprolol 5mg", "Ramipril 10mg",
        "Atorvastatin 40mg", "Furosemide 40mg", "Spironolactone 25mg",
        "Metformin 500mg", "Amlodipine 5mg",
    ], k=rng.randint(0, 4))
    return {"medications": meds}


def seed_clinical_study(db: Session, seed: int = 42) -> dict:
    """
    Generate and persist the full CARDIO-2024 demo dataset.
    Clears existing clinical data first (idempotent).
    Returns summary counts.
    """
    rng = random.Random(seed)

    # Clear existing
    db.query(ClinicalForm).delete()
    db.query(ClinicalVisit).delete()
    db.query(ClinicalSubject).delete()
    db.query(ClinicalStudy).delete()
    db.commit()

    # Create study
    study = ClinicalStudy(**STUDY_DEF)
    db.add(study)
    db.flush()  # get study.id

    enrollment_start = date(2024, 1, 15)
    subject_count = 0
    visit_count = 0
    form_count = 0

    for i in range(20):
        site_id, site_name = rng.choice(SITES)
        enroll_offset = rng.randint(0, 120)
        enroll_date = enrollment_start + timedelta(days=enroll_offset)
        sex = rng.choice(["M", "F"])
        subj_status = _weighted(rng, SUBJECT_STATUSES)

        subject = ClinicalSubject(
            study_id=study.id,
            subject_key=f"CARDIO-2024-{i+1:03d}",
            site_id=site_id,
            site_name=site_name,
            age=rng.randint(45, 80),
            sex=sex,
            race=rng.choice(RACES),
            enrollment_date=enroll_date,
            status=subj_status,
        )
        db.add(subject)
        db.flush()
        subject_count += 1

        n_visits = len(VISITS) if subj_status == "Completed" else rng.randint(2, 5)

        for v_idx, (v_oid, v_name, v_day_offset) in enumerate(VISITS[:n_visits]):
            visit_date = enroll_date + timedelta(days=v_day_offset)
            visit = ClinicalVisit(
                subject_id=subject.id,
                visit_oid=v_oid,
                visit_name=v_name,
                visit_date=visit_date,
                status="Completed",
            )
            db.add(visit)
            db.flush()
            visit_count += 1

            # Form: Vital Signs
            db.add(ClinicalForm(
                visit_id=visit.id, form_oid="VS", form_name="Vital Signs",
                data_json=json.dumps(_generate_vitals(rng, v_idx))
            ))
            # Form: Adverse Events
            db.add(ClinicalForm(
                visit_id=visit.id, form_oid="AE", form_name="Adverse Events",
                data_json=json.dumps(_generate_aes(rng, v_idx))
            ))
            # Form: Concomitant Medications
            db.add(ClinicalForm(
                visit_id=visit.id, form_oid="CM", form_name="Concomitant Medications",
                data_json=json.dumps(_generate_meds(rng))
            ))
            # Form: Lab Results
            db.add(ClinicalForm(
                visit_id=visit.id, form_oid="LB", form_name="Lab Results",
                data_json=json.dumps(_generate_labs(rng))
            ))
            form_count += 4

    db.commit()
    return {
        "study": study.study_oid,
        "subjects": subject_count,
        "visits": visit_count,
        "forms": form_count,
    }

## 5. Alembic Migration: `003_pgvector_and_clinical.py`

This is the most critical migration. It must:
1. Enable the pgvector extension
2. Create four clinical tables
3. Create `document_chunks` with a `vector(768)` column (raw DDL)
4. Create the IVFFlat index for cosine similarity search

Revises: 002

        sa.Column("data_json", sa.Text),

Note: The migration uses HNSW (Hierarchical Navigable Small World) index rather than IVFFlat because HNSW works on an empty table and does not require a training step. IVFFlat requires at least `lists * 40` rows to be present. Since this table starts empty, HNSW is the correct choice. pgvector >= 0.5.0 supports HNSW, and the `pgvector/pgvector:pg15` Docker image ships 0.7.0+.

Key decisions:
- `pgvector/pgvector:pg15` is the official image published by the pgvector project; it is identical to `postgres:15` but ships with the extension pre-compiled. No custom Dockerfile needed for the db container.
- The Ollama `entrypoint` uses a background `ollama serve` + `sleep 5` + model pulls approach. The `sleep 5` gives the server time to initialize before issuing pull commands. Both models are pulled at container start; if already in the volume they are no-ops.
- `pg_data` volume is added to persist database data across container restarts (was missing in the original compose).
- The backend now `depends_on: ollama` so Docker Compose starts Ollama first, though the backend code uses `ollama_ready()` checks to gracefully handle Ollama not yet being ready.

## 12. Migration Strategy and Sequencing

The implementation must follow this exact order because each step depends on the previous:

**Step 1: Docker Compose update**

Change `db` image from `postgres:15` to `pgvector/pgvector:pg15`. This is required before any migration can run because the migration executes `CREATE EXTENSION IF NOT EXISTS vector`. The pgvector-enabled image ships the shared library; the standard postgres:15 image does not.

## 13. Embedding Generation and Storage: Data Flow at Ingestion Time

```
POST /rag/ingest
  |
  v
routers/rag.py::ingest()
  - checks ollama_ready()
  - calls ingestion_service.ingest_all(db)
  |
  v
services/ingestion.py::ingest_all(db)
  - queries ClinicalStudy -> ClinicalSubject -> ClinicalVisit -> ClinicalForm
  - for each entity type, calls _upsert_chunk(db, source_type, source_id, text, metadata)
  |
  v
services/ingestion.py::_upsert_chunk()
  1. DELETE existing document_chunks WHERE source_type=X AND source_id=Y
  2. calls llm.embed_text(chunk_text)
  |
  v
services/llm.py::embed_text()
  - POST http://ollama:11434/api/embeddings
  - body: {"model": "nomic-embed-text", "prompt": chunk_text}
  - returns list[float] of length 768
  |
  v (back in _upsert_chunk)
  3. formats vector as "[0.123,0.456,...]"
  4. db.execute(raw SQL INSERT with CAST(:embedding AS vector))
  5. row stored in document_chunks with embedding column as vector(768) type in Postgres
  |
  v
db.commit() after all chunks for the current entity
```

Chunk volumes for the full 20-subject CARDIO-2024 demo:
- 1 study chunk = 1
- 20 subject chunks = 20
- ~75 visits x 1 visit summary chunk = ~75
- ~75 visits x (0-2) AE chunks avg ~1.2 = ~90
- ~75 visits x (0-1) abnormal lab chunks at 20% rate = ~15
- **Total: ~200 chunks, ~200 Ollama embedding calls**

Each `nomic-embed-text` embedding call takes approximately 50-200ms on CPU. Total ingestion time: 10-40 seconds on CPU Ollama.

## 14. RAG Retrieval: Data Flow at Query Time

```
POST /rag/chat  {"question": "Which subjects had severe adverse events?", "top_k": 5}
  |
  v
routers/rag.py::chat()
  - checks ollama_ready()
  - calls rag_service.answer_question(db, question, top_k=5)
  |
  v
services/rag.py::answer_question()
  calls retrieve_chunks(db, question, top_k=5)
  |
  v
services/rag.py::retrieve_chunks()
  1. calls llm.embed_text(question)
     - POST http://ollama:11434/api/embeddings
     - returns 768-dim question vector
  2. formats as "[0.1,0.2,...]"
  3. db.execute(raw SQL):
     SELECT ... 1 - (embedding <=> CAST(:q_vec AS vector)) AS similarity
     FROM document_chunks
     ORDER BY embedding <=> CAST(:q_vec AS vector)    -- cosine distance, HNSW index used
     LIMIT 5
  4. returns list of 5 most relevant chunks with similarity scores
  |
  v (back in answer_question)
  calls build_prompt(question, chunks)
  - assembles prompt: [Source 1 - adverse_event]\n<chunk_text>\n\n ... \n\nQuestion: ...\n\nAnswer:
  |
  v
  calls llm.generate_text(prompt, system=SYSTEM_PROMPT)
  - POST http://ollama:11434/api/generate
  - body: {"model": "tinyllama", "prompt": "...", "stream": false, "system": "..."}
  - returns generated string (typically 2-5 seconds on CPU)
  |
  v
returns {
  "answer": "Subjects CARDIO-2024-007 and CARDIO-2024-015 experienced severe adverse events...",
  "sources": [
    {"chunk_text": "Adverse event for subject CARDIO-2024-007...", "source_type": "adverse_event",
     "source_id": 23, "similarity": 0.94},
    ...
  ],
  "model": "tinyllama"
}
```

The `<=>` operator is pgvector's cosine distance operator. `1 - (embedding <=> q_vec)` converts distance to similarity score (0 to 1, higher is more similar). The HNSW index means this query is ANN (approximate nearest neighbor) rather than exact KNN, but for 200 chunks the difference is negligible and the index still provides a performance floor for when the corpus grows.

## 16. Anticipated Challenges and Mitigations

**Challenge 1: `Base` circular import between `models.py` and `models_clinical.py`**

`models_clinical.py` does `from models import Base`. This is safe as long as `models.py` does not import from `models_clinical.py`. The import is one-directional. In `main.py`, import `models_clinical` after `models` is already imported.

**Challenge 2: Ollama model download time on first startup**

`nomic-embed-text` is ~274MB and `tinyllama` is ~638MB. The Docker `entrypoint` script pulls both at container start, which can take several minutes. The backend's `ollama_ready()` check and the `/rag/status` endpoint allow the frontend to show a "warming up" state rather than an error. The healthcheck `start_period: 120s` gives Ollama time to initialize before other containers consider it healthy.

**Challenge 3: pgvector extension not present on existing `postgres:15` container**

Changing the image to `pgvector/pgvector:pg15` will re-initialize the database if no volume is mounted. The original `docker-compose.yml` has no volume for `pg_data`, meaning the database is lost on every `docker compose down`. The new compose adds a named volume `pg_data:` which also means any existing data in the ephemeral container is gone on rebuild — but this is acceptable since it was ephemeral anyway.

**Challenge 4: Raw SQL for vector operations bypasses ORM type safety**

All vector insert/query operations use `db.execute(text(...))`. Parameter names must be spelled consistently. Use the exact parameter approach shown: `CAST(:embedding AS vector)` in the SQL string with a plain string value `"[0.1,0.2,...]"` passed as the parameter.

**Challenge 5: Ingest timeout from browser perspective**

The `/rag/ingest` endpoint is synchronous and will run for 10-40 seconds for 200 chunks. The `frontend` uses `requests.post(..., timeout=300)` (5 minutes). A Streamlit spinner wraps the call. For very large datasets in the future, this should be made async with a job queue, but for the 200-chunk demo it is acceptable as a synchronous call.
